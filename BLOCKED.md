### Multi-character run support
- **Surface:** `src/Sts2Headless/HostMethods.cs:98-101` — `if (character != Character.Ironclad) throw new ArgumentException("...not yet supported (only Ironclad)")`. `Sts2Bindings.StartIroncladRun` is the only available entry point on the bindings layer.
- **Question:** Which characters to add and in what order (Silent / Defect / Watcher / Regent / Necrobinder), and whether `bindings.StartIroncladRun` should become `StartRun(character, …)` or a per-character family (`StartSilentRun`, …). Either shape needs character-specific starting decks, relics, and engine-side bootstrap differences.
- **Cheapest unblock:** Pick one new character (suggest Silent — closest to Ironclad in run shape) and confirm whether the bindings layer takes a character enum or stays per-character. Once decided, multi-character coverage in `CoverageSweepTests.s_runs` follows mechanically.
- **Discovered:** 2026-05-18 via fill-engine-gaps TODO scan (pass 1b) + coverage delta (pass 1c). The coverage report classifies ~80% of missing Cards/Relics/Powers as "off-class content the sweep cannot reach with single-character runs".

### Move-body patches that strip boss damage (Doormaker-shape audit)
- **Surface:** `src/Sts2Headless.Runtime/Patches/HangPatches.Monsters.cs` — the remaining monster patch entries pass move/lifecycle methods whose bodies still contain gameplay mutations.
- **Blast radius (2026-05-23, post-cleanup):** **17 patched methods** still strip at least one gameplay mutator (down from 61 baseline 2026-05-21). The snapshot is locked into `tests/Sts2Headless.IntegrationTests/MonsterPatchAuditTests.cs` (`s_expectedDoormakerShape`). Breakdown by monster:
  - **Crusher** (6): all 5 attack moves + AfterAddedToRoom — body unconditionally dereferences `Crusher.get_Background()` which is null in headless (no boss-background node). Needs a per-monster Background stub or per-call null gate.
  - **Rocket** (5): same shape as Crusher (`Rocket.get_Background()`).
  - **LagavulinMatriarch.AfterAddedToRoom**: body legitimately puts the monster to sleep; encounter sweep then reports InProgress=false because nothing wakes it.
  - **SlumberingBeetle.AfterAddedToRoom**: same sleep-state shape.
  - **SoulNexus.{AfterDeath, BeforeRemovedFromRoom}**: unconditional `NCombatRoom.get_Instance` dereference on the killing-blow path (auditor doesn't flag these — no gameplay mutators in body — but they're still patched defensively).
  - **Tunneler.BelowMove**: unconditional `Godot.Node2D.set_Position` to position the tunneler under the player.
  - **Vantom.DismemberMove**: BossRoom hang at round 3 after partial body execution; CombatRoom encounter sweep doesn't reproduce. Root NRE site not yet isolated.
- **2026-05-23 cleanup wave:** Dropped strips for 11 monsters (Vantom initially included, then re-added — see commit 93bebd3) after IL probing confirmed TestMode.IsOn=true + BootstrapSequence.SetTestMode covers their UI gating. Monsters fully unstrip'd: BowlbugRock, CeremonialBeast, CorpseSlug, DecimillipedeSegment, GremlinMerc, TerrorEel, TestSubject, TheInsatiable, ThievingHopper; LagavulinMatriarch partial (kept AfterAddedToRoom only); SoulNexus partial (kept lifecycle hooks only); Tunneler partial (kept BelowMove only); SlumberingBeetle partial (kept AfterAddedToRoom only). Audit shrank 61 → 17 entries.
- **Cheapest unblock (DONE 2026-05-21):** `MonsterPatchAuditor` + `MonsterPatchAuditTests`. Adding a new monster patch with gameplay-mutating moves fails the audit until either the leaf-helper fix is applied (Doormaker-style) or the line is added to the expected list with a written justification.
- **Next unblock (PER REMAINING MONSTER):** Crusher + Rocket need a stub or null-gate for `get_Background()` (likely the highest leverage — together they account for 11/17 remaining entries). Vantom needs the BossRoom-vs-CombatRoom NRE site identified. Lagavulin / Beetle sleep-state needs either the sweep fixture to wake them or the AfterAddedToRoom body to gate sleep on a TestMode flag. SoulNexus lifecycle hooks need null-gating on NCombatRoom.Instance.
- **Discovered:** 2026-05-21 during the Doormaker investigation; quantified later the same day via `MonsterPatchAuditor`. Cleanup wave 2026-05-23.

### Treasure room previewable pick/skip
- **Surface:** `src/Sts2Headless.Protocol/MethodCatalog.cs:69` — `run/leave_treasure_room` summary explicitly mentions a "future slice can split this into previewable pick/skip". Today the engine's `TreasureRoomRelicSynchronizer` auto-picks the single relic offering on entry; the wire method just exits to MapRoom.
- **Question:** Two-step shape — does it become `run/preview_treasure_room` (returns the relic offering) + `run/pick_treasure_room` (accept or skip), or a single `run/leave_treasure_room(skip: bool)` with the preview surfaced through the existing snapshot's `treasureRoom` block? The two-step preview is cleaner but adds a new method; the param-on-leave is non-breaking but less symmetric with merchant/event flows.
- **Cheapest unblock:** Confirm whether previewability is a CURRENT need (replay determinism? agent decision-making?) or speculative. If speculative, leave the catalog summary as-is and revisit when a caller surfaces.
- **Discovered:** 2026-05-18 via fill-engine-gaps catalog scan (pass 1a).
