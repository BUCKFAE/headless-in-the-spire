_(Multi-character run support graduated 2026-05-23 — went with `bindings.StartRun(Character, seed, withNeow, ascensionLevel)` (single entry point) over a per-character family. `Sts2Bindings.Bind` iterates `Enum.GetValues<Character>()` and resolves one closed-generic `Player.CreateForNewRun<TCharacter>` per value into an `IReadOnlyDictionary<Character, MethodInfo>` — a missing character type fails Bind() at host startup. Three layers of defense against "added enum value, forgot to wire it": (1) `CharacterExtensions.Sts2TypeName` is a switch expression with no default arm, and `Sts2Headless.Protocol.csproj` promotes CS8509 to an error so the build breaks at compile time; (2) `CharacterEnumCoverageTests` in `Sts2Headless.UnitTests` (no sts2.dll) asserts every enum value maps; (3) Bind() throws at runtime. Watcher dropped from the enum — STS2 has five characters per `documentation/sts2-game-facts.md` (Ironclad, Silent, Defect, Regent, Necrobinder); the dead enum value would only have produced "not yet supported" at the host before, and now produces an unambiguous "unknown enum value" at parse time. Coverage in `tests/Sts2Headless.IntegrationTests/MultiCharacterStartRunTests.cs` — `[Theory]` over each character, asserts run/new lands at MapRoom and run/state reports a live player. Doesn't yet wire characters into `CoverageSweepTests.s_runs`: each character may surface its own Doormaker-shape monster patches (Silent-only / Regent-only / Necrobinder-only encounters), and the sweep would surface those as crashes attributable to coverage rather than to per-character monster patching. That follow-up is one extension at a time, in the same shape as the Ironclad sweep.)_
