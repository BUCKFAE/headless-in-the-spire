# /refresh-docs

Narrative docs in this repo go stale fast. By a wide margin, the most
common failure mode is **a doc claims something is "still open / future
slice / not yet / planned / blocked" for something that already
shipped**. Implementation summaries also drift (e.g. "patched with a
no-op prefix" when the current fix is a transpiler), and renamed symbols
leave dead pointers.

This skill exists to catch all three — but optimise for the first.

## Mental model

Three kinds of staleness, in priority order:

1. **Status drift (the big one).** "still open / future slice / not yet
   wired / planned / blocked / TODO / WIP / next slice / forthcoming /
   soon" — for something that already landed. Evidence sources:
   - `git log --oneline -100` for recent commits.
   - `BLOCKED.md` graduated trailers (live blockers are at the top,
     graduated entries at the bottom in `_(... graduated YYYY-MM-DD ...)_`
     format).
   - Existence + passing of a named test (`dotnet test --filter Name~X`).
   - A symbol now resolving in `src/` where the doc says it doesn't.
2. **Implementation drift.** Accurate when written, wrong now. Look for
   sentences that describe HOW: "no-op prefix", "returns null", "wraps
   in try-catch", "auto-picks last option", "skip body and return
   default", "Harmony patches every X to no-op". For each, find the
   cited symbol and compare to its current shape.
3. **Reference drift.** File paths, type names, `just` recipes, env
   vars, wire methods, test names. Verify each still exists. Numerical
   counts (sweep totals, gap counts, "Doormaker shape: N entries") are
   reference drift too — they get out of date silently.

## Pre-flight (main context)

- `git status` clean. If not, stop and report.
- `git log --oneline -100` — the evidence corpus for shipped work.
- `git log --oneline BLOCKED.md` — when BLOCKED.md last graduated something.
- Read `BLOCKED.md` top section (live blockers) so you can spot
  "this is still open" claims that BLOCKED.md confirms.

## Phase 1 — Parallel evidence-gathering (one Explore subagent per doc)

Pick the audit set. Default:

- `README.md`
- `BLOCKED.md` (live entries only — the `_(... graduated ...)_` trailers
  are frozen history and must not be rewritten)
- `documentation/sts2-game-facts.md`
- `documentation/testing.md`
- `documentation/research/agent-survival-gaps.md`
- `documentation/research/replay-recording-and-viewing.md`
- `documentation/research/self-verification.md`
- `documentation/research/sts2-cli-anatomy.md`
- `documentation/research/mcp-integration.md`
- `documentation/research/e2e-testing-and-self-feedback.md`
- `documentation/research/existing-headless-libraries.md`
- `documentation/research/general-sts2-modding.md`
- `documentation/research/schema-description-format.md`
- `documentation/runbooks/*.md`
- `documentation/requirements/03-extra-goals.md` (open goals — same
  audit shape as a research doc; safe to edit)

**Skip:**

- `documentation/research/seed42-recon.md` — 4600-line reconnaissance
  dump; non-narrative, regenerated by hand on demand.
- `documentation/research/natural-chain-gaps.md`,
  `documentation/research/reward-chain-gaps.md` — regenerated by
  `just runner::probe::natural-chain` / `just runner::probe::rewards-natural-chain`.
  Never hand-edit.
- `documentation/coverage/` — gitignored sweep output.
- `documentation/research/modeldb/` — gitignored probe output.
- `documentation/human-notes/` — the user's working notes.
- `CLAUDE.md` and `documentation/requirements/01-initial-goals.md` /
  `02-architecture-decisions.md` — load-bearing. Surface drift only;
  do NOT autoedit. ADs are referenced by AD-N elsewhere; never
  renumber.

Launch every audit in ONE message with multiple `Agent` calls so they
run concurrently. Use the **Explore** subagent (read-only).

### Subagent prompt template

Substitute the bracketed fields. Pass absolute paths.

```
Audit <ABS-DOC-PATH> for stale claims. Repo root is <ABS-REPO-ROOT>.

Three drift patterns to catch, in priority order:

1. STATUS DRIFT (highest priority — the dominant pattern in this repo).
   For every sentence claiming something is "still open / not yet /
   future slice / planned / blocked / TODO / WIP / next slice /
   forthcoming / soon" or similar, do all of:
     a. Name the file:line and the symbol/file/recipe/test it references.
     b. Search src/ + tests/ for the symbol. If present, read enough
        of the surrounding code to judge whether the doc's claim still
        holds.
     c. Check `git log --oneline --all -- <relevant path>` and
        `git log --oneline -100 --grep=<keyword>` for a shipped commit.
     d. Check BLOCKED.md for a `_(... <Title> graduated YYYY-MM-DD ...)_`
        trailer covering the topic.
   Report per finding: file:line | claim (quoted, ≤80 chars) | evidence
   (commit SHA / test name / BLOCKED trailer / current code excerpt) |
   verdict (STALE / STILL OPEN / UNCERTAIN).

2. IMPLEMENTATION DRIFT. Sentences describing HOW something works
   ("no-op prefix", "returns null", "wraps in try-catch", "Harmony
   patches every X to no-op", "stub returns default"). For each, find
   the cited symbol in src/ and quote its current shape (1-3 lines of
   actual code). Report: file:line | doc claim | current shape |
   verdict (MATCHES / DIFFERS).

3. REFERENCE DRIFT. File paths, type names, `just` recipes (run
   `just --list` to verify), env vars, wire methods, test names, and
   numerical counts (sweep totals, "audit: N entries", gap counts).
   For each: still valid? Report: file:line | reference | verdict
   (LIVE / DEAD / DRIFTED) | suggested replacement.

Constraints:
- READ ONLY. Do NOT edit the doc.
- Output one markdown report to stdout. Cap at 600 words.
- High-signal findings only. UNCERTAIN goes in a separate trailing
  section, not mixed with the verdicts.
- If the doc is already accurate, say so in one line and stop.
- Pass commit SHAs in 7-char short form. Quote enough of a current-code
  excerpt that the orchestrator doesn't need to re-grep.

Output structure:

  ## <doc basename>
  ### Status drift
  - file:line | "<quoted claim>" | <evidence> | STALE
  ...
  ### Implementation drift
  - file:line | "<quoted claim>" | <current shape> | DIFFERS
  ...
  ### Reference drift
  - file:line | <reference> | DEAD → <replacement>
  ...
  ### Uncertain
  - file:line | <claim> | <why uncertain>
```

## Phase 2 — Triage (main context)

Merge subagent reports. Build a per-doc edit plan. For each finding:

- **STALE (status drift)** — high priority. Rewrite the claim to reflect
  what landed. The replacement usually mirrors a BLOCKED.md graduated
  trailer's shape: one sentence naming what landed + a commit SHA or
  test name as proof. If the original sentence was an entire "still
  open" section, the replacement may simply delete it (with a one-line
  "resolved YYYY-MM-DD via <commit>" if surrounding text still refers
  to it).
- **DIFFERS (implementation drift)** — rewrite the description to match
  the current code. Quote the new shape correctly; don't paraphrase
  loosely.
- **DEAD / DRIFTED (reference drift)** — replace the reference with the
  live one. If it's gone for good, delete the surrounding sentence
  rather than leave a hanging pointer.
- **UNCERTAIN** — surface to the user verbatim. Don't guess.

State the plan briefly to the user before applying:

> "I'll apply these edits across N docs. M findings are clear-cut
> (STALE / DIFFERS / DEAD); K are UNCERTAIN — listed below for your
> call."

If the user pushes back on any specific edit, drop it from the plan.

## Phase 3 — Apply edits, one commit per doc

For each doc with confirmed findings:

1. Apply edits with `Edit` (or `Write` if the rewrite is large enough to
   warrant a full pass).
2. Commit immediately. Template:

   ```
   docs(<doc-basename>): refresh stale claims

   - <bullet per finding, ≤72 chars each>

   Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
   ```

   Scope examples: `docs(agent-survival-gaps)`, `docs(BLOCKED)`,
   `docs(README)`, `docs(replay-recording)`.

3. Let the pre-commit hook run. Never `--no-verify`. If the hook
   regenerates anything (it shouldn't for doc-only edits, but watch
   for stray protocol/_models drift), restage and commit again — never
   amend.

4. Move to the next doc. Do **not** bundle multiple docs into one
   commit; small commits make the audit trail navigable when a future
   reader is wondering "when did this claim get updated, and why?".

## Special cases

- **BLOCKED.md live blockers.** If a top-section blocker has actually
  shipped, move it down to the trailer section in the canonical
  `_(<Title> graduated YYYY-MM-DD — <one-paragraph summary>)_` format
  that surrounding trailers use. Read 3-4 existing trailers first to
  match tone and length. Never rewrite an existing trailer.
- **agent-survival-gaps.md.** Hand-written narrative; safe to edit.
  Sister files `natural-chain-gaps.md` / `reward-chain-gaps.md` are
  probe output — skip them.
- **requirements/02-architecture-decisions.md and CLAUDE.md.** Surface
  drift only. Never autoedit. AD numbering must never change.
- **README.md.** Keep it brief. If a finding would expand the README
  beyond the current scope, route it to a research doc instead.
- **Numerical counts.** Re-run the underlying probe / read the current
  file count before changing a count in a doc — never just bump by a
  guess. If the count comes from a sweep report under
  `documentation/coverage/` and the report is missing or older than
  `GAME_VERSION`, flag the doc as UNCERTAIN instead of editing.

## Hard guardrails

1. Never edit `documentation/coverage/`,
   `documentation/research/modeldb/`,
   `documentation/research/natural-chain-gaps.md`,
   `documentation/research/reward-chain-gaps.md` — regenerated, not
   authored.
2. Never edit `CLAUDE.md`, `documentation/requirements/01-initial-goals.md`,
   `documentation/requirements/02-architecture-decisions.md`, or
   `documentation/human-notes/*` without explicit user approval.
3. Never rewrite an existing BLOCKED.md `_(... graduated ...)_`
   trailer. Move live entries into a new trailer; leave history alone.
4. Never invent a commit SHA, test name, or symbol shape to back a
   "this shipped" claim. If the evidence isn't real, the finding is
   UNCERTAIN — surface to the user.
5. Never `--no-verify`. Never amend. Never squash. Never push.
6. One commit per doc. The next reader needs to be able to bisect a
   "wait, was this true two months ago?" question without unbundling.
7. Don't bump `GAME_VERSION`, sweep snapshots, or the
   `MonsterPatchAudit` expected list as part of doc cleanup — those
   are owned by their workflows.

## When to STOP and ask

- Conflicting evidence (git log says shipped, but the test it points
  at is red).
- A doc reads as deliberate past-tense narrative ("the bug was X; we
  fixed it by Y"). Rewriting past tense for present-tense correctness
  destroys context. Surface; don't edit.
- A finding hinges on judgment (the symbol changed shape but the
  doc's INTENT may still hold).
- Queue exhausted — give a one-paragraph summary: which docs got
  refreshed (commit SHAs, one bullet each), which findings went to
  UNCERTAIN, anything that should land in BLOCKED.md as a follow-up.

## Subagent usage cheatsheet

- **Explore** — the right tool for Phase 1 audits. Read-only, fast,
  bounded report size.
- **general-purpose** — only if a doc audit balloons into "we need to
  actually run a probe to confirm"; otherwise stick with Explore.
- **Plan** — when a rewrite is large enough that you want to sketch
  the new doc structure before editing.

Bundle the Phase 1 audits in ONE message with N parallel `Agent` calls.
That's the only way they run concurrently.
